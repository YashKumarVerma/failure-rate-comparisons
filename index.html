What to try
  1. Kill traffic. Set both sliders to 0. Level estimators (per-event) freeze at the last value; rate estimators decay to 0; fixed-tick ratio becomes 0/0 and the line disappears. Redis cost: per-event designs drop to read cost only; fixed-tick keeps paying for ticks.
  2. Error spike. Jump failure/s from 10 to 100 for a few seconds, then back. Compare how fast each line reacts and how long it takes to forget (max err column, and the error chart). The sliding window has a hard edge; EWMAs fade.
  3. Scale traffic. Push success/s to 1000 with the sliding window on zset. Memory grows with traffic × W; switch to buckets and watch memory flatten while reads get more expensive.
  4. Read per request. Tick "reads = traffic" (e.g. a circuit breaker checks on every call). Bucketed sliding windows multiply cost by W / bucket per read.
  5. Low traffic. Drop success/s to 5 and failure/s to 1. Per-event fixed α slows to a crawl (memory is in events, not seconds); time-decayed τ keeps the same reaction time but gets noisier.
  6. Tick vs τ. Fixed-tick with interval Δ and α behaves like τ ≈ −Δ / ln(1 − α). The card shows the equivalent τ live.

Error rate on Redis: implementation handover

Six ways to track a per-stream error rate in Redis, with the exact Redis commands, Lua scripts and trade-offs. Scripts were run against Redis 7. The Simulator tab shows how each one behaves and what it costs at your traffic.

Recommendation: A. Decayed counts. One hash per stream, one Lua call per request (or per batch), no background job. It gives the error ratio and the request rate, so a breaker can refuse to trip on low volume. With no traffic the ratio holds its last value while the rates decay to 0, which is the behaviour you want from both.

Rules that apply to every option

  • Use Redis's clock, not the app's. Scripts call TIME so every host shares one clock. Needs Redis ≥ 5 (scripts replicate effects by default).
  • Hash-tag the stream id (err:{merchant_42}). All keys a script touches must be in one cluster slot.
  • Return floats as strings. Redis converts Lua numbers to integers in replies, so 0.1 would come back as 0.
  • Load scripts with go-redis redis.NewScript. Run sends EVALSHA and falls back to EVAL after a restart or failover.
  • Set a TTL on every key so idle streams clean themselves up. For decayed state, 5τ loses nothing (<1% weight left).
  • Hot streams. All writes for one stream run one at a time on one shard. Above a few thousand requests/s per stream, pre-aggregate per host (see Scaling).

A. Decayed counts recommended

Keep two exponentially decayed counters per stream: failures f and all requests a. Each request adds 1/τ; both decay by e^(−Δt/τ). Then a ≈ requests/s, f ≈ failures/s, and f / a = error ratio. Because both decay by the same factor, the ratio does not change during silence.

Key
err:{stream} hash: f, a, ts
Params
τ seconds (reaction time), ttl = 5τ
Batching
Pass counts: ARGV = failures, requests. One request = 1,1 or 0,1.

Write

lua
-- KEYS[1] = err:{stream}
-- ARGV[1] = failures   ARGV[2] = requests (1/1 or 0/1 per event, or batched counts)
-- ARGV[3] = tau (s)    ARGV[4] = ttl (s)
local t = redis.call('TIME')
local now = tonumber(t[1]) + tonumber(t[2]) / 1e6
local nf, n, tau = tonumber(ARGV[1]), tonumber(ARGV[2]), tonumber(ARGV[3])
local s = redis.call('HMGET', KEYS[1], 'f', 'a', 'ts')
local f, a, ts = tonumber(s[1]) or 0, tonumber(s[2]) or 0, tonumber(s[3]) or now
local k = math.exp(-math.max(0, now - ts) / tau)
f = f * k + nf / tau
a = a * k + n / tau
redis.call('HSET', KEYS[1], 'f', tostring(f), 'a', tostring(a), 'ts', tostring(now))
redis.call('EXPIRE', KEYS[1], ARGV[4])
return tostring(a > 0 and f / a or 0)

Read

lua
-- KEYS[1] = err:{stream}   ARGV[1] = tau (s)
-- returns { error_ratio, requests_per_s, failures_per_s } as strings
local t = redis.call('TIME')
local now = tonumber(t[1]) + tonumber(t[2]) / 1e6
local s = redis.call('HMGET', KEYS[1], 'f', 'a', 'ts')
if not s[2] then return { '0', '0', '0' } end
local k = math.exp(-math.max(0, now - tonumber(s[3])) / tonumber(ARGV[1]))
local f, a = tonumber(s[1]) * k, tonumber(s[2]) * k
return { tostring(f / a), tostring(a), tostring(f) }

If you only need the ratio, a plain HMGET err:{stream} f a and f / a on the client is enough: decay cancels out of the ratio. Use the script when you also need the rate (volume guard).

Go

go
// go-redis v9. Script.Run uses EVALSHA and falls back to EVAL on NOSCRIPT.
var (
	recordErr = redis.NewScript(dcRecordLua) // dc_record.lua above
	readErr   = redis.NewScript(dcReadLua)   // dc_read.lua above
)

const (
	tau    = 10        // seconds; see "Choosing τ"
	ttl    = 5 * tau   // after 5τ the state is <1% of its value
	minRPS = 2.0       // volume guard: don't judge a stream on a handful of requests
)

func key(stream string) []string { return []string{"err:{" + stream + "}"} }

// Record one request outcome. For high traffic, batch per host and pass counts instead.
func Record(ctx context.Context, rdb redis.Scripter, stream string, failed bool) error {
	f := 0
	if failed {
		f = 1
	}
	return recordErr.Run(ctx, rdb, key(stream), f, 1, tau, ttl).Err()
}

// ErrorRate returns the smoothed error ratio and request rate for a stream.
func ErrorRate(ctx context.Context, rdb redis.Scripter, stream string) (ratio, rps float64, err error) {
	v, err := readErr.Run(ctx, rdb, key(stream), tau).StringSlice()
	if err != nil {
		return 0, 0, err
	}
	ratio, _ = strconv.ParseFloat(v[0], 64)
	rps, _ = strconv.ParseFloat(v[1], 64)
	return ratio, rps, nil
}

func ShouldTrip(ratio, rps, threshold float64) bool {
	return rps >= minRPS && ratio >= threshold
}

B. Time-decayed level

A single EWMA of the outcome (x = 1 failure, 0 success), weighted by time since the previous request. Same cost as A, but it stores no volume, so after a cold start (or TTL expiry) the first request sets the ratio to 0% or 100%. You cannot guard against that without a second counter, at which point you have built A.

Key
lvl:{stream} hash: v, ts
Read
HGET lvl:{stream} v
lua
-- KEYS[1] = lvl:{stream}   ARGV[1] = 1 if failure else 0   ARGV[2] = tau (s)   ARGV[3] = ttl (s)
local t = redis.call('TIME')
local now = tonumber(t[1]) + tonumber(t[2]) / 1e6
local x, tau = tonumber(ARGV[1]), tonumber(ARGV[2])
local s = redis.call('HMGET', KEYS[1], 'v', 'ts')
local v = tonumber(s[1])
if v == nil then
  v = x
else
  v = v + (1 - math.exp(-math.max(0, now - tonumber(s[2])) / tau)) * (x - v)
end
redis.call('HSET', KEYS[1], 'v', tostring(v), 'ts', tostring(now))
redis.call('EXPIRE', KEYS[1], ARGV[3])
return tostring(v)

C. Fixed-tick EWMA

Requests only increment a counter. A single ticker (one elected host) runs a script per stream every interval Δ that turns the counts into a rate and smooths it with α. Equivalent τ ≈ −Δ / ln(1 − α); Δ = 1 s, α = 0.2 gives τ ≈ 4.5 s.

  • The cheapest write path: one O(1) command, no Lua.
  • The ticker must know every active stream: keep a registry (SADD streams <id>, one more command per request) or a known list.
  • The ticker costs Redis load even with zero traffic: streams ÷ Δ scripts/s.
  • If the ticker stalls, the estimate stops moving. The script divides by real elapsed time, so a late tick does not inflate the rate.
  • With zero traffic both rates decay to 0 and the ratio is 0/0; the script returns 0. Treat a ratio with rate below your volume guard as "unknown".

Write, per request

redis
# every request (no Lua)
HINCRBY cnt:{stream} ok 1      # or: HINCRBY cnt:{stream} fail 1

# leader election for the ticker, renewed every interval
SET ticker:lock <host-id> NX PX <2 × interval_ms>

Tick, per stream every Δ

lua
-- KEYS[1] = cnt:{stream}   KEYS[2] = ewma:{stream}   ARGV[1] = alpha   ARGV[2] = ttl (s)
-- run by ONE ticker every interval, per stream. Divides by real elapsed time, so a late tick does not inflate the rate.
local t = redis.call('TIME')
local now = tonumber(t[1]) + tonumber(t[2]) / 1e6
local alpha = tonumber(ARGV[1])
local c = redis.call('HMGET', KEYS[1], 'ok', 'fail')
redis.call('DEL', KEYS[1])
local ok, fail = tonumber(c[1]) or 0, tonumber(c[2]) or 0
local e = redis.call('HMGET', KEYS[2], 'f', 'a', 'ts')
local last = tonumber(e[3])
if last == nil then
  redis.call('HSET', KEYS[2], 'ts', tostring(now))
  redis.call('EXPIRE', KEYS[2], ARGV[2])
  return nil
end
local dt = math.max(now - last, 0.001)
local rf, ra = fail / dt, (ok + fail) / dt
local ef, ea = tonumber(e[1]), tonumber(e[2])
if ef == nil then ef, ea = rf, ra else ef = ef + alpha * (rf - ef); ea = ea + alpha * (ra - ea) end
redis.call('HSET', KEYS[2], 'f', tostring(ef), 'a', tostring(ea), 'ts', tostring(now))
redis.call('EXPIRE', KEYS[2], ARGV[2])
return { tostring(ea > 0 and ef / ea or 0), tostring(ea), tostring(ef) }

Read: HMGET ewma:{stream} f a, ratio = f / a.

D. Sliding window, sorted set

Every request becomes a sorted-set member scored by its timestamp. Exact counts over the last W seconds, and the simplest to explain in a postmortem. Memory and work grow with traffic: at 1,000 requests/s and W = 60 s that is 60,000 members (~7 MB) per stream, and a hot stream's trims and counts get slower as the set grows.

  • The member must be unique per request (request id), or same-millisecond requests overwrite each other.
  • Failures go into a second set so the read is two ZCOUNTs, not a scan.

Write

lua
-- KEYS[1] = sw:all:{stream}   KEYS[2] = sw:fail:{stream}
-- ARGV[1] = 1 if failure else 0   ARGV[2] = W (s)   ARGV[3] = unique request id
local t = redis.call('TIME')
local now = tonumber(t[1]) * 1000 + math.floor(tonumber(t[2]) / 1000)
local wms = tonumber(ARGV[2]) * 1000
local function add(key)
  redis.call('ZADD', key, now, ARGV[3])
  redis.call('ZREMRANGEBYSCORE', key, '-inf', now - wms)
  redis.call('PEXPIRE', key, wms)
end
add(KEYS[1])
if ARGV[1] == '1' then add(KEYS[2]) end
return 1

Read

lua
-- KEYS[1] = sw:all:{stream}   KEYS[2] = sw:fail:{stream}   ARGV[1] = W (s)
-- returns { error_ratio, requests_per_s, failures_per_s }
local t = redis.call('TIME')
local now = tonumber(t[1]) * 1000 + math.floor(tonumber(t[2]) / 1000)
local from = '(' .. (now - tonumber(ARGV[1]) * 1000)
local a = redis.call('ZCOUNT', KEYS[1], from, '+inf')
local f = redis.call('ZCOUNT', KEYS[2], from, '+inf')
local w = tonumber(ARGV[1])
return { tostring(a > 0 and f / a or 0), tostring(a / w), tostring(f / w) }

E. Sliding window, bucketed counters

One counter key per time bucket, expiring on its own. Memory is fixed (2·W/bucket keys per stream), writes are plain commands, but every read fetches every bucket. With W = 60 s and 1 s buckets that is a 120-key MGET per read, which hurts if you read on every request.

  • Bucket ids come from the app clock; keep bucket width well above clock skew (NTP: ~ms, so ≥ 1 s is safe).
  • The current bucket is partial, so the window is really W − bucket to W. Smaller buckets fix that at the cost of more keys.
redis
# client side, pipelined (no Lua). b = floor(now_ms / bucket_ms), k = W / bucket
INCR   sw:{stream}:a:<b>
EXPIRE sw:{stream}:a:<b> <W + bucket>
# on failure only:
INCR   sw:{stream}:f:<b>
EXPIRE sw:{stream}:f:<b> <W + bucket>

# read: one MGET of 2k keys (same hash tag, so one slot in cluster)
MGET sw:{stream}:a:<b-k+1> ... sw:{stream}:a:<b>  sw:{stream}:f:<b-k+1> ... sw:{stream}:f:<b>
# ratio = Σf / Σa ; rate = Σa / W   (missing keys = 0)

F. Per-event fixed α avoid

Ignores time: memory is about 1/α requests, not seconds. At peak traffic it reacts in milliseconds and at night in minutes, so one threshold cannot work for both. Listed for completeness.

lua
-- KEYS[1] = a:{stream}   ARGV[1] = 1 if failure else 0   ARGV[2] = alpha   ARGV[3] = ttl (s)
local v = tonumber(redis.call('GET', KEYS[1]))
local x = tonumber(ARGV[1])
if v == nil then v = x else v = v + tonumber(ARGV[2]) * (x - v) end
redis.call('SET', KEYS[1], tostring(v), 'EX', ARGV[3])
return tostring(v)

Choosing τ

For A, B and C, when the true error ratio jumps from p₀ to p₁, the estimate crosses a threshold θ after

t = τ · ln( (p₁ − p₀) / (p₁ − θ) )

Example: τ = 10 s, a jump from 1% to 50% errors and a 25% threshold → t = 10 · ln(0.49 / 0.25) ≈ 6.7 s. Smaller τ trips faster but is noisier at low traffic; use the simulator's error chart to see the noise floor at your real request rate.

Scaling

  • Pre-aggregate per host. Count locally and flush every 100–250 ms with one A-script call carrying the counts. Redis load becomes hosts × flushes/s per stream, independent of traffic. With flush interval ≪ τ the accuracy loss is negligible.
  • Reads are often the bigger cost. A breaker that checks Redis on every request doubles the round trips. Cache the decision per host for ~100 ms, or read it back from the flush call (the A script already returns the ratio).
  • Total load ≈ streams × (writes/s + reads/s) per stream. The Cost vs accuracy table on the Simulator tab computes this for your numbers.
go
// Per host, per stream: accumulate for flushEvery, then one script call.
// Redis load becomes hosts × (1/flushEvery) per stream, independent of traffic.
type counter struct{ fail, total atomic.Int64 }

func (c *counter) flush(ctx context.Context, rdb redis.Scripter, stream string) {
	n, f := c.total.Swap(0), c.fail.Swap(0)
	if n == 0 {
		return
	}
	_ = recordErr.Run(ctx, rdb, key(stream), f, n, tau, ttl).Err()
}

Tests to write

  1. Steady state: 90 successes + 10 failures/s for 5τ → ratio ≈ 0.10, rate ≈ 100/s (within 5%).
  2. Silence: stop traffic for 2τ → ratio unchanged, rate ≈ 100 · e^(−2) ≈ 13.5/s.
  3. Step: jump to 50% errors → crosses 25% at the time the τ formula predicts (±20% for Poisson noise).
  4. Cold start / TTL expiry: one failure on an empty key → ratio 100% but rate ≈ 1/τ, so the volume guard blocks a trip.
  5. Concurrency: N goroutines recording in parallel → same totals as sequential (scripts are atomic).
  6. Failover: flush the script cache (SCRIPT FLUSH) → next call still succeeds via the EVAL fallback.
